# Eligibility generation: original-source checks

Method version: `original-source-v2` (2026-11-17). Interaction policy: `direct-draft-v1`, with sentence topics and source-ambiguity confirmations (2026-11-18).

## Behaviour

The preliminary model pass organizes the framework and may propose at most two important, unspecified restrictions as complete optional rules; no questions or fill-in forms are requested. Its proposed rules are retained for audit only and never used as source evidence. Extraction reads the original question and complete extracted document text in bounded chunks; the previous 3,000-character context truncation is removed. PDF page numbers, document identifiers and exact chunk offsets are retained. An `Other` domain can carry explicit report restrictions without inventing a study-design restriction.

An extracted proposition must quote a source passage, retain its numeric constraints, and pass a separate semantic review against both that passage and its surrounding original context. Recognizable source constraints that were not converted are recorded in the saved audit. A second semantic review checks rewritten wording, including its logical scope and possible conflicts. If polishing omits an already reviewed required or prohibited atom, its unchanged proposition can be rendered directly with its source link. A faulty rewrite can also be replaced by the already reviewed original proposition. Unverified atoms, genuine source conflicts and allowed propositions do not qualify for that recovery path. Both calls use the selected model: they are separate checks, **not statistically independent reviewers**.

Deterministic checks compare common numerical values, bounds, units, temporal direction and roles, and detect selected AND/OR, negation and exception changes. They also check that cited propositions' numerical constraints are not omitted. These checks supplement semantic review; they are not a complete clinical language parser or a formal equivalence proof. Supported unit conversions and unusually expressed conditions can conservatively be omitted with a diagnostic note; missing optional scope stays unrestricted, while genuine source ambiguity or conflicting original requirements can produce concrete author choices.

Synthesis uses a compact JSON Schema through the existing model endpoint, checks response structure in the application, and retries a malformed structure at most once using the original atoms. Missing dimensions are filled only by empty arrays; reviewed atomic wording provides the omission recovery described above, never invented filler.

Final rules retain their atom links in `ruleEvidence`; atoms retain original source names, page information, offsets and quotations. Surrounding context can be reconstructed from the saved snapshots and offsets, without duplicating every source chunk in storage. Missing or duplicate semantic review results become uncertain. Conflicting identical inclusion/exclusion rules are removed from both sides and flagged. Oversized context fails with a request for a focused excerpt rather than silently losing text or evidence.

The preliminary pass summarizes the original research question in one concise, complete English sentence beginning “This review”, covering population, intervention/exposure/concept, comparator and outcomes only when supplied. Topic normalization rejects framework fragments, multiple sentences, overlong summaries and unsupported numeric additions; old P:/I: topics use a sentence fallback from the active rules. Author-edited topics remain editable and are preserved. The Description is derived from accepted rules. Automatic Description updates after rule edits or clarification decisions use the current effective rules. An explicit user edit to Description remains an author decision and is logged rather than labelled as automatically checked.

## Direct drafts and optional important restrictions

Generate displays the source-backed Inclusion, Exclusion and Description directly. It does not create a required questionnaire, fill-in fields, Reviewed buttons or per-rule meets/fails choices. Unspecified restrictions remain absent from the active criteria. Unsupported model rewrites are omitted or repaired automatically, with their diagnostics preserved in the saved audit. Actual ambiguous source requirements remain outside active criteria until the author confirms an interpretation. Internal diagnostics are not shown as a user task list. A separate **Confirm unclear criteria** section offers complete, source-linked interpretations with Include/Exclude buttons and no input fields. Only original-source ambiguity/conflict or an explicitly undecided requirement produces these cards; model errors and routine review notices do not. Confirmation immediately updates the selected side, removes an opposing version of the same ambiguous rule, preserves unrelated criteria, regenerates Description, saves the author decision and updates downstream handoff. Confirmations remain available even when every source rule is initially ambiguous. Failed saves roll back the choice and rules; a confirmed card stays resolved after reload. The same display policy applies to existing drafts without changing their active or previously author-confirmed rules. Saving, export, navigation and task completion do not require answering suggestions.

When the original source leaves a consequential restriction unspecified, the preliminary pass may propose at most **two** optional, complete rules with a short reason. The UI offers **Adopt** and **Keep current criteria**; it contains no blanks. Generic optional details, repetitive questions, placeholders and arbitrary new numeric thresholds are not displayed. The model is instructed to return no suggestions when none is important. Suggestions in a domain already awaiting source confirmation are suppressed to avoid duplicate requests. These are author-selectable scope proposals, not source evidence, and remain outside the active criteria and Description until adopted. Adoption preserves the proposed inclusion/exclusion side, updates the full Description, saves an author-decision record and updates downstream handoff. Keeping the draft never creates a complementary exclusion. Both choices persist across reload; failed saves restore the prior state.

Outcome interests are not automatically outcome-reporting eligibility requirements. Missing population/central concept, language, dates, design or comparator information does not create a compulsory question. Existing legacy question and decision records remain saved as history, without reopening the earlier workflow.

Image inputs are first transcribed with the selected vision model. Unreadable or uncertain transcription stops generation and preserves the saved draft. Legible transcription goes through the same extraction, constraint checks and semantic review as text, and supported rules appear directly in the generated draft. Source metadata labels these as `image-transcription`, never verified original text. The legacy `visual-review-required` marker is read compatibly as transcription provenance and does not create an adoption gate.

## Records, compatibility and publication

The saved refinement includes original extracted text snapshots and their SHA-256 hashes when Web Crypto is available, method version, resolved model names, requested temperature, prompt/response hashes, rule assessments and author decisions. Actual server sampling settings are labelled as unreported when the response does not provide them; temperature zero is not represented as a reproducibility guarantee. API keys, authorization headers and image base64 payloads are not added to this audit record.

Author-confirmed rules are visible and editable in Inclusion/Exclusion immediately, persist on reload, and appear in the full Description, Word export and downstream handoff. Earlier confirmed rules had been intentionally filtered out of the page; that filter is now removed, including for existing saved drafts. Explicit later edits replace the active wording; the previous author decision remains historical and is marked superseded in Word when appropriate. Original source excerpts and automatic check notes remain in the saved workspace/audit only. They do not appear in Eligibility, the shared screening previews, the public criteria summary or the default Word export; original snapshots, hashes, source links and confirmation evidence are retained in storage. Existing saved drafts remain intact and show that the new checks require regeneration. Original attachment files must be reattached after a browser reload before regenerating an attachment-based draft; Clear explicitly permits starting again from text alone. The existing Save, Clear, generation-method lock, embedded editors and downstream handoff are preserved.

The normal GitHub Pages main-branch deployment ships the HTML and shared JavaScript changes. No backend configuration or model change is required.

## Verification and limits

`node tools/test_eligibility_grounding.cjs` exercises the actual page code with a controlled model transport, including forged source quotations, omitted constraints, reversed bounds, changed units, temporal direction, scope swaps, logical combinations, uncertainty, direct generation from image transcription, optional suggestion adoption/dismissal, save/reload and Description consistency. Its fixture has separate development/test sections and a SHA-256 lock to make subsequent changes explicit. These are synthetic regression cases developed alongside the implementation, **not an untouched independent test set or an expert-validated clinical benchmark**.

Live testing also exposed a syntactically valid but structurally incomplete synthesis response. Schema-constrained synthesis, application-level structure checks and unchanged-atom recovery address this failure; recorded live outputs are replayed through the updated pipeline in addition to controlled-transport tests.

On 2026-11-17, targeted live checks with `gemma4:31b-it-q8_0` accepted the correct age/follow-up paraphrase and rejected the reversed age bound and changed follow-up unit. This small check is not full end-to-end clinical validation; an initial three-rule request exceeded a 30-second verification-client timeout. Production retains its existing ten-minute generation limit. Browser visual verification and the jsdom-dependent routing and full localization tests were unavailable in this environment (jsdom is not installed).

On 2026-11-18, a fresh local-model check returned a concise complete topic sentence covering exercise, usual care, pain and adults with fibromyalgia. A separate source review classified “Randomized trials may be eligible” as `ambiguous_source`; the application produced ready-to-select inclusion/exclusion interpretations. These targeted checks supplement the controlled-transport regressions and do not establish clinical accuracy.

A separate, expert-adjudicated evaluation across real review topics remains necessary before making accuracy or workload-reduction claims. Freeze those projects before prompt tuning, keep development and evaluation topics separate, repeat model runs, record disagreements and measure downstream false exclusions as well as rule correctness and omissions. Do not publish synthetic regression pass rates as clinical accuracy.

The broader `test_protocol_imports.cjs` check still fails its pending-background-import assertion in the unchanged Proposal workspace code; this is separate from eligibility generation. Relevant eligibility, embedded-editor, clearing, task-status and screening prompt checks are run for this change.

These checks describe product behavior rather than a measured reduction in clinical review workload.

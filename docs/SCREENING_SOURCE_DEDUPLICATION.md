# Screening source：导入、文献去重与输出技术说明

实现版本：`report-dedup-v3`。本文对应 `app/screening-dedup.js` 与 `title-abstract-screening.html`，记录本工具的工程规则；这些阈值尚未通过独立真实文献数据集验证。

## 1. 功能与数据边界

Screening source 接收两种来源：用户从上一步 Search strategy 选择导入的检索批次，以及从本地文件解析的记录。两类输入统一清洗后进入同一个去重引擎。RIS/NBIB 解析保留卷号、期号和页码；源数据 RIS 导出同时保存带明确 PMID 标签的注释，以支持标识符往返导入。

去重单位是“同一篇报告的数据库记录”。同一研究的方案、结果、随访、会议摘要、勘误等可能是不同报告，不能仅因内容相似就自动删除。关联同一研究的多篇报告属于后续研究级管理。[1]

输出包括：

1. 完整去重集合 `source.records`，供 Pilot screening 抽样和正式筛选使用；
2. 同一集合的 RIS、CSV、BibTeX 和 JSON 本地导出，已有筛选决定不会缩小源数据导出范围；
3. JSON 去重审计：原始成员、字段来源、合并理由、相似度、疑似记录对及相关历史筛选归档。

“完成去重”不等于“确定所有保留记录绝无重复”。疑似重复全部保持独立，直接进入 Pilot 抽样和正式筛选。页面不要求用户确认合并、保持分开或暂不处理；疑似数量仅作说明和审计用途。信息不足、没有进入疑似列表的记录也分别保留。

## 2. 与旧实现的变化

| 旧实现 | 当前实现 |
|---|---|
| 卷号、期号、页码共同缺失可以得到匹配分数 1 | 缺失字段不提供正向匹配证据 |
| 其他文本高度相似时可能忽略 DOI 冲突 | 不同有效 DOI 或 PMID 阻止自动合并，转为疑似重复 |
| 摘要仅比较前 500 字符 | 全部清洗后的摘要参与词项相似度计算 |
| 先导入记录的非空摘要一直保留 | 选择更长的可用摘要，保存所有原始版本和字段来源 |
| 在已有主记录上补字段，但比较索引不更新 | 所有原始记录独立建立索引，不依赖主记录补字段 |
| 遇到首个匹配立即合并 | 先生成候选关系，再执行有组内约束的归并 |
| 疑似重复需要另行处理 | 疑似重复统一保留并直接筛选，页面仅提供只读去重信息和审计导出 |
| 本地源数据导出仅包含尚未决定的记录 | 源数据导出包含完整去重集合，与 Pilot 共用数据源 |

当前实现借鉴规则式、多字段去重思路，但不应称为 ASySD 原版的等价移植。ASySD 的研究性能属于其指定软件版本和评估数据，不能移用于本工具。[2]

## 3. 记录与标识符规范化

每条输入包括 `uid`、标题、摘要、作者、年份、期刊、卷号、期号、页码、DOI、PMID、URL 和来源信息。

用于比较的文本执行 Unicode NFKD 规范化、去组合音标、大写化、非字母数字字符转空格、连续空白归一化。原始书目字段另外保留，比较文本不会覆盖原文。

DOI 处理去除 `doi:` 和 DOI URL 前缀、解码百分号编码、去首尾空白并转小写。仅符合 `10.<4–9 位数字>/<非空无空白后缀>` 的值参与 DOI 标识符匹配。这是格式检查，不是 DOI 注册或真实性验证。

PMID 必须全部为数字，去除多余前导零。无效字符串不参与 PMID 精确匹配。

作者拼接为文本后规范化；完全为 `UNKNOWN` 或 `ANONYMOUS` 的作者按缺失处理。年份取四位数字。期刊使用规范化文本，不调用期刊缩写解析服务。

## 4. 候选记录配对（blocking）

只有共享至少一个分组键的原始记录才进行详细比较：

- 规范化 DOI；
- 规范化 PMID；
- 完整规范化标题；
- 标题前 40 个字符；
- 标题前 4 个词；
- 作者文本首个词与年份；
- 期刊、卷号与页码；
- 年份、卷号与页码。

所有原始成员均参与建索引。假如 A 缺少 DOI，B 带有 DOI 且匹配 A，后续 C 仍能通过 B 的原始 DOI 找到候选关系，不会因 A 的旧比较字段而漏掉这条关系。

Blocking 降低通常情况下的计算量，但也会漏掉没有任何共同键的真实重复。它不是全量两两比较，也不保证线性时间；当大量记录共享作者、年份或标题前缀时，候选数最坏可达到二次量级。

## 5. 相似度

### 5.1 标题与作者：Jaro–Winkler

设匹配字符数为 m，半换位数为 t，字符串长度为 |a|、|b|：

`J = (m/|a| + m/|b| + (m-t)/m) / 3`

`JW = J + 0.1 × l × (1-J)`

其中 l 为最多 4 个字符的共同前缀长度；无匹配字符时为 0。任一字段缺失时不产生支持证据。

相似度是字符串指标，不能解释为属于同一报告的概率。

### 5.2 摘要：全摘要词项集合 Sørensen–Dice

规范化后完整摘要以空格切词，形成不同词项的集合 A、B：

`Dice(A,B) = 2 × |A∩B| / (|A|+|B|)`

任一集合为空时为 0。不再只读取摘要前 500 个字符。

词项集合不保留词序或词频，不能判断语义等价或逻辑关系。高度相似摘要需要其他书目信息共同支持，不能单独触发自动合并。中日韩等不以空格分词的文本不具备同等分词质量，是当前方法的适用边界。

## 6. 单对记录决策

### 6.1 相关性预判

存在以下任一条件才进入重复或疑似重复处理：

- 有效 DOI 完全相同；
- 有效 PMID 完全相同；
- 标题 JW ≥ 0.85，且作者 JW ≥ 0.75、期刊非空且完全一致、摘要 Dice ≥ 0.80 三者至少满足一项。

否则本次候选比较判为不同记录。该结论仅代表当前规则未识别为相关，不能证明其绝非重复。

### 6.2 自动合并的保护条件

相关记录出现以下情况时转为疑似重复，不自动合并：

- 双方均有有效 DOI，但不相同；
- 双方均有有效 PMID，但不相同；
- 双方年份均存在，且相差超过 1 年；
- 标题中识别到的报告类型不同；
- 两个非空标题中的数字或独立罗马数字序列不同。

报告类型仅检查 `PROTOCOL`、`ERRATUM`、`CORRECTION`、`RETRACTION` 和 `COMMENTARY` 等显式词，不是完整的语义分类器。数字保护比较阿拉伯数字与独立的 I/V/X 组合，可减少不同试验编号、报告部分或时间点的误合并，但也可能增加疑似重复。

### 6.3 自动合并规则

在上述保护条件全部通过后，满足以下任一规则才自动合并：

| 规则 | 条件 |
|---|---|
| R1 | 有效 PMID 完全一致 |
| R2 | 有效 DOI 完全一致 |
| R3 | 标题 JW ≥ 0.97；作者 JW ≥ 0.95；年份存在且一致；期刊存在且一致；卷号存在且一致；页码存在且一致 |
| R4 | 非空标题完全一致；作者 JW ≥ 0.95；年份存在且一致；期刊存在且一致；两段摘要各至少 160 个规范化字符、各至少 20 个不同词项；全摘要 Dice ≥ 0.98 |

R3、R4 额外要求：双方同时存在的卷号、期号或页码不能不同。R1、R2 不强求这些出版字段一致，以容纳标识符一致但数据库著录不同的情形。

没有达到自动合并条件的相关候选保留为疑似重复。

以上阈值是当前保守工程配置，尚未由基准数据确定为最优值。提高自动合并门槛可能减少误合并，也可能增加漏重及后续筛选工作量。

## 7. 重复组构建与桥接保护

输入批次按导入时间排序，同时间再按批次键排序；批次内保留文件或检索结果的原始顺序。相同输入会得到相同结果；改变批次传入数组的排列不改变结果。更改导入时间或批次内顺序不保证标识与主记录相同。

候选边按相同 PMID、相同 DOI、其他自动规则排序，同级使用固定键排序。

自动连接两个重复组前，检查所有跨组成员对：每一对都必须满足自动重复条件。任何跨组成员对为疑似或不符合自动重复规则时，两个组不自动合并。由此避免仅凭 A≈B、B≈C 就将相互冲突的 A、C 自动合并。

这里使用并查集维护组关系，但自动归并采用跨组全对检查约束，并非直接合并候选图的所有连通分量。

## 8. 主记录与字段保留

每组以最早排序成员的 UID 为基础保留筛选记录身份。不同保留记录出现相同 UID 时，生成额外 UID，避免后续以 UID 存储筛选结果时互相覆盖。

字段在组内独立选择：

- DOI、PMID 优先选择通过格式校验的值；
- 可用字段优先选择字符串更长的值；
- 作者按拼接后的字符串长度选择；
- 相同长度时按稳定成员键打破平局；
- 合并成员的全部来源，完全相同的来源对象仅保存一次。

因此，摘要优先保留较长版本，同时每个原始摘要都存在于审计成员中。更长不必然等于质量更好，这是可复现的选择策略，不是对内容质量的模型判断。

每个字段记录其来源成员 `fieldSources`。RIS/CSV/BibTeX 的单值字段输出选中的主值；JSON 审计保留全部原始成员及其字段。具有有效标识符冲突的疑似记录分别输出，不提供人工合并覆盖。

## 9. 疑似重复保留与只读审计

疑似重复采用固定策略：全部保留为独立记录，直接进入 Pilot 抽样与后续正式筛选；不建立人工去重任务、不弹出去重确认，也不提供合并、保持分开、暂不处理、拆分或重置决定的按钮。

Screening source 的 Deduplication details 仅展示自动合并组、依据和原始成员；其下方导出区域提供独立的 `Export deplication` 按钮（中文界面为“导出重复记录”），下载 Excel（.xlsx）文件，无需展开详情。仅在确实存在自动合并删除的重复记录时启用；未导入、没有重复，或只有疑似重复时均禁用。自动合并组每次展示 20 组，可展开更多。疑似记录对保存在审计中，不要求用户逐对处理。

疑似计数单位为“成员记录对”，不等于涉及的独特报告数，也不从 To screen 或 Pilot 候选集合中扣除。Pilot 仍按既有每轮样本量从全部保留记录中抽样，不表示每条疑似记录都会进入同一轮 Pilot。

成员键包含批次、原始位置、UID 与内容校验值，用于原始成员追溯和源数据变更检测。校验值为非密码学指纹，不构成防篡改保证。

版本 3 不读取旧版人工去重选择来改变活动集合。旧选择仅以 `legacyReviewerDecisions` 保留在审计中。页面加载、导入以及后台刷新时，系统自动比较记录与标准指纹；变化时先归档已有筛选结果，再采用最新集合并重置预筛批准，不再显示 Use latest source 按钮，也不要求点击同步或弹出同步确认。未变化时不重置、不重复归档。保存失败恢复旧工作区并保留错误提示，后续自动刷新可重试。已有结果被归档时只显示简短状态，新的预筛启动后状态清除。筛选或人工编辑期间暂停后台刷新；具体筛选标准仍需按原有流程保存和批准。

## 10. 输出与审计格式

源数据导出的范围固定为完整 `source.records`，与 Pilot 抽样使用同一数组。To screen 仍表示尚未决定的数量，它不会改变源数据 Export 的范围。

格式选择集成在 Export 按钮的下拉菜单中，点击 Export 展开 RIS、CSV、BibTeX、JSON 四种格式，选择后直接下载并关闭菜单。支持键盘上下键、Home/End、Escape 及点击外部关闭；没有可导出记录时按钮禁用。页面不再单独显示 Format 标签和选择框。

`Export deplication` 按钮生成单个工作表的 Excel（.xlsx）。第一行固定五列，第二行开始每行对应一条已自动合并删除的重复记录：

| ID号 | 标题 | 作者 | 年份 | 重复理由 |
|---|---|---|---|---|
| 原始输入记录的 UID | 原始标题 | 全部作者以分号分隔 | 原始年份 | 中文匹配理由及保留记录 ID |

工作表名为 `Duplications`，冻结第一行并启用筛选；文件名为 `duplications-<日期>.xlsx`。ID 以文本保存以保留前导零，类似公式的原始文本不会被执行。

导出仅包含每个自动合并组中被删除的成员，不包含该组保留的主记录、独特记录或仅疑似重复的记录。因此数据行数与页面 Duplicates removed 一致。没有已删除重复记录时，不生成空文件。

重复理由由实际合并记录生成：PMID 相同、DOI 相同、标题/作者/出版信息满足匹配规则，或标题与完整摘要等信息满足匹配规则，并标明合并后的保留记录 ID。不再导出 Records、Matches、Summary 或 Long text 等额外工作表和审计字段。

JSON 源数据导出仍包含完整 `deduplication` 审计（包括历史数据），其格式为 `aimstep-deduplication-audit/v3`，包括：

- 算法版本及源数据指纹；
- 导入、保留、删除重复记录数；
- 每组原始成员及其批次；
- 每个输出字段的来源；
- 自动合并理由与比较分数；
- 已保留并直接用于筛选的疑似成员对；
- `retain-possible` 处理策略、只供追溯的旧版人工选择及历史筛选归档。

数量关系为：`导入有效记录数 = 保留记录数 + 合并掉的重复记录数`。该关系只验证数量一致，不能证明重复判定正确。

去重引擎不调用模型，也不执行资格筛选。去重本身在浏览器中进行；之后的 Pilot 模型请求仍遵循筛选页面已有的模型连接流程。

## 11. 验证与限制

执行：

```sh
node tools/test_screening_dedup.cjs
node tools/test_screening_source_sync.cjs
node tools/test_screening_dedup_export.cjs
node tools/test_screening_stages.cjs
node tools/test_screening_stages_save.cjs
node tools/test_screening_clear.cjs
```

新增去重检查使用合成记录、模拟页面/存储和实际 Excel 文件的 ZIP/XML 结构校验，覆盖标识符冲突、缺失字段、不同编号报告、全摘要差异、组内桥接冲突、原始索引、完整摘要及来源保留、批次传入顺序、旧版人工选择不再覆盖当前规则、无人工去重操作入口、源数据切换的保存失败回滚与旧结果归档、四种格式完整源数据导出及 Pilot 共用数据，还覆盖实际 source 加载函数的两类导入合流、事务内禁止提前保存以及 RIS/NBIB 元数据往返。

这些检查验证实现行为，不估计真实数据上的准确率。当前环境没有可用的浏览器连接，尚未进行真实浏览器中的视觉与交互核验。

仍需要使用公开去重基准及本工具实际数据建立报告级人工参考分组，分别报告：独特记录误合并数、重复记录漏识别数、疑似记录对数量、疑似保留导致的额外筛选工作量，以及运行时间/内存。不同导入顺序、非英文文献、错误标识符、会议摘要、正式论文和随访报告应单独评估。公开比较研究显示不同工具在误删、漏重和耗时之间存在权衡，没有一项指标可以代表全部质量。[3]

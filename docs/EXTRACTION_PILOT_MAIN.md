# Pilot extract and Main extract

Implemented 8 October 2026, following the application's screening-stage interaction pattern.

Pilot extract samples readable included reports without replacement within a round (1–20, default 3). The AI draft displays study fields, all-arm TIDieR items, outcome results and source quotations. Missing returned fields appear as blanks. Reviewers choose Agree or Mistake; Mistake permits value edits and requires a saved reason. All reports in at least one current round must be reviewed before approval. Further rounds are optional. The displayed AI accuracy is the proportion of sampled reports marked Agree, not field-level accuracy or an independent model benchmark.

Main extract requires approval for the current extraction form and included-report signature. It reads all available included reports, retains successful drafts, supports Stop/Resume, and links to the existing per-value verification/correction and confirmation editor. All records, Check and Completed filters distinguish generated drafts from human-confirmed studies. Unreadable PDFs remain listed for manual review rather than disappearing. Confirmed data continue through the existing Analysis handoff.

Confirmed pilot correction notes and changed values are supplied to later rounds and Main extract as extraction guidance, never as source evidence for another report. Raw drafts and corrected copies remain in project-scoped IndexedDB. Changes to form definitions or the included-report signature invalidate approval. Changes to learned corrections invalidate unfinished main-generation markers; unverified AI cells can be refreshed, while manually edited or verified cells and arm IDs remain. Source order and arm mapping still require human verification.

Clear actions require confirmation. Pilot Clear removes round reviews/approval; Main Clear resets generation progress. Saved study values and PDFs are retained. Generation runs lock form edits and source mutations. Save failures stop generation and roll back the just-generated entry. Approval/review-save failures roll back workflow state. Error messages remain visible; routine generation text is replaced with the purple progress bar. Help appears on hover/focus. The source-panel AI toolbar previously removed at the user's request remains removed.

Public pages use the existing authenticated online transport to the Mac Studio local model; local pages retain their local-server connection. No key is embedded and the model provider is unchanged. Online embeddings use keyword retrieval fallback to avoid public-browser localhost requests. Stop cancels the transport request; backend jobs use the existing transport's cleanup.

Other information: the earlier change only stopped seeding new projects. Existing system-generated Other fields (including previous generic outcome defaults moved there) are now removed from active and restorable form lists. Their definitions are retained in a background archive and study values are not destroyed. Explicitly added custom items remain. Cleanup runs on initialization, so old auto-defaults cannot return on refresh.

Validation: pure tests cover approval, round completion, report-level accuracy, correction transfer, form-signature invalidation, sampling, omitted-field normalization, refreshing only unverified AI values and legacy Other cleanup. Browser tests use an isolated three-report synthetic project and mocked AI responses, checking random two-report pilot, Agree/Mistake + reason/edit Save, 50% accuracy, approval gate, Main Stop/Resume without duplicate calls, correction propagation, three drafts, two-arm 24-item reviewer, refresh persistence and old-default removal. These workflow tests do not constitute a real-model accuracy evaluation; the underlying extraction model was tested separately in the all-arm work.

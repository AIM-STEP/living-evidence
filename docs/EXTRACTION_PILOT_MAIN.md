# Pilot extract and Main extract

Implemented 8 October 2026, following the application's screening-stage interaction pattern.

Pilot extract samples readable included reports without replacement within a round (1–20, default 3). The AI draft displays study fields, all-arm TIDieR items, outcome results and source quotations. Missing returned fields appear as blanks. Reviewers choose Agree or Mistake; Mistake permits value edits and requires a saved reason. All reports in at least one current round must be reviewed before approval. Further rounds are optional. The displayed AI accuracy is the proportion of sampled reports marked Agree, not field-level accuracy or an independent model benchmark.

Main extract requires approval for the current extraction form and included-report signature. It reads all available included reports, retains successful drafts, supports Stop/Resume, and links to the existing per-value verification/correction and confirmation editor. All records, Check and Completed filters distinguish generated drafts from human-confirmed studies. Unreadable PDFs remain listed for manual review rather than disappearing. Confirmed data continue through the existing Analysis handoff.

Confirmed pilot correction notes and changed values are supplied to later rounds and Main extract as extraction guidance, never as source evidence for another report. Raw drafts and corrected copies remain in project-scoped IndexedDB. Changes to form definitions or the included-report signature invalidate approval. Changes to learned corrections invalidate unfinished main-generation markers; unverified AI cells can be refreshed, while manually edited or verified cells and arm IDs remain. Source order and arm mapping still require human verification.

Clear actions require confirmation. Pilot Clear removes round reviews/approval; Main Clear resets generation progress. Saved study values and PDFs are retained. Generation runs lock form edits and source mutations. Save failures stop generation and roll back the just-generated entry. Approval/review-save failures roll back workflow state. Error messages remain visible; routine generation text is replaced with the purple progress bar. Help appears on hover/focus. The source-panel AI toolbar previously removed at the user's request remains removed.

Public pages use the existing authenticated online transport to the Mac Studio local model; local pages retain their local-server connection. No key is embedded and the model provider is unchanged. Online embeddings use keyword retrieval fallback to avoid public-browser localhost requests. Stop cancels the transport request; backend jobs use the existing transport's cleanup.

Other information: the earlier change only stopped seeding new projects. Existing system-generated Other fields (including previous generic outcome defaults moved there) are now removed from active and restorable form lists. Their definitions are retained in a background archive and study values are not destroyed. Explicitly added custom items remain. Cleanup runs on initialization, so old auto-defaults cannot return on refresh.

Validation: pure tests cover approval, round completion, report-level accuracy, correction transfer, form-signature invalidation, sampling, omitted-field normalization, refreshing only unverified AI values and legacy Other cleanup. Browser tests use an isolated three-report synthetic project and mocked AI responses, checking random two-report pilot, Agree/Mistake + reason/edit Save, 50% accuracy, approval gate, Main Stop/Resume without duplicate calls, correction propagation, three drafts, two-arm 24-item reviewer, refresh persistence and old-default removal. These workflow tests do not constitute a real-model accuracy evaluation; the underlying extraction model was tested separately in the all-arm work.

## Excel export and missing values

Pilot extract exports the selected round; Main extract exports reports with saved extraction results. Both Export buttons create a local `.xlsx` with one sheet per active extraction section. Items are rows and reports are columns; arm and outcome/time-point combinations have separate columns. Rows 1–3 are always ID, Author and Year, with the first column and those rows frozen. Saved pilot corrections and main reviewer edits take precedence. New rounds retain a form snapshot. Source quotations/passages and review status accompany values; additional AI time points not covered by the main reviewer remain labelled as requiring review. No model call or upload occurs during export.

All extraction items use NR for unreported information and NA for demonstrably inapplicable information. Omission alone must not become NA. Explicit zero is preserved. Legacy blank values are normalized on display/export without rewriting the original audit history. AI instructions and built-in definitions use the same convention. Numeric validation accepts these markers, still validates reported numeric companions, and excludes incomplete numeric rows from analysis hand-off. Unstarted reports are not exported as if extraction had happened. Excel strings are written as literal text, preventing formula injection.

## Direct local import and AI feedback

Import from local opens the file chooser and imports immediately. There is no import dialog, preview, naming requirement, merge/replace choice or confirmation step. The filename supplies the initial form name. Business-level file-count, file-size, field-length/count and required-definition gates do not apply to this direct import; native Office decoding retains technical archive-integrity/resource checks. Multiple files can supply a form and its definitions together. Matching items combine, while conflicting definitions remain visible as separate items for review.

The new Local import entry and original files are persisted before AI review. Missing definitions remain explicitly empty, rather than receiving generic defaults or definitions from another form. Native XLSX/DOCX/CSV/TSV/JSON/text structures are parsed locally. Unstructured readable documents (including PDF) can be transcribed during review, accepting only names/definitions present verbatim in supplied text. Unreadable files are retained with a diagnostic; they are not represented as successfully read.

The existing model adapter checks all imported items in batches for missing definitions, ambiguity and duplicates, without imposing irrelevant study requirements. Deterministic missing-definition checks remain alongside AI suggestions. Feedback is displayed under the imported form, with Check again on completion/failure. Model failure never rolls back the imported form. Pending checks resume after refresh; feedback writes target the original form ID, so switching forms does not mix results. AI can append operational supplements to missing/incomplete definitions using exact item IDs from its batch. Existing definitions are preserved in the text and per-field history (original, addition, reason, model and timestamp); duplicates and unknown IDs are ignored. AI additions can be reviewed in Edit. Uncertain requirements are left for review. Local import automatically collapses Generation Method and its generation controls; the header toggle can reopen them. Edit opens an inline draft of the imported form. Icon buttons appear in Edit → Check again → Save → Export order. Export downloads a new uniquely named XLSX with a blank Extraction form sheet, separate Items definition sheet, and configured outcome targets when present. It exports the current inline draft if open, otherwise the saved form; it never writes to uploaded files. Check again reviews current unsaved edits; Save updates the same form ID and creation date, including edited definitions and completed feedback. Further edits invalidate that draft feedback. Missing definitions remain allowed and are flagged. Saved form revisions are retained; changed forms invalidate pilot approval/main completion and mark prior AI values unverified while retaining manual values.

## Three form creation methods and catalogue

The Generation Method selector follows Eligibility criteria: Manual generate and Machine generate. Local import stays beside the Extraction form collapse button. The existing six-section editor and definition dialogs edit a separately persisted manual draft; Generate creates a named saved form. Editing a saved Manual/Machine form opens a manual copy, so draft changes do not silently modify an active extraction form.

Machine generate accepts written requirements and up to six files (PDF, DOCX, XLSX, TXT, Markdown, CSV, TSV or JSON; 10 MB per file, 100,000 total extracted characters). It uses the existing authenticated/local model adapter, asks for structured extraction items and operational definitions, validates the response and enforces identity fields and NR/NA conventions. Full Excel source cell content is retained as source material. Missing/unreadable/oversized materials and invalid model output do not create a form. Stop aborts the request and does not save a partial form. The supplied material, model and generation date are retained as provenance.

All saved forms appear in the Extraction form header above its dividing line and generation controls, showing name, creation date/time, origin, item count and Current status, with a rightmost delete icon. Names expand items/definitions; Use activates a form; Edit opens imported forms inline and copies generated forms to Manual generate. Each form has its own studies and Pilot/Main flow. Switching captures the active results before restoring the selected form's results. Deletion requires confirmation and affects that form's results; shared included reports and PDFs remain. Legacy workspaces are migrated into one existing form without losing results. All state is project-scoped; failed persistence rolls back catalogue and active results together.

Generate actions sit on the Manual/Machine heading rows, with matching purple progress bars and percentages inside. Progress reflects workflow stages, not model token completion: machine materials ready (25%), response received (50%), form validated (75%), persisted (100%); manual validation (50%) and persistence (100%). Stop/failure resets progress without creating a partial form.
